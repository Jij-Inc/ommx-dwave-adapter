# Adapter conversion benchmark results

2026年8月31日実施のOMMX v2/v3ローカル測定結果です。

## 結論

- v3 regularはv2比で一律なデグレはありません。30ケースの中央値は、Instance → Model時間が6.7%減、Result → Solution時間が0.6%減でした。
- v3 regularのピークメモリ中央値はv2比で、Instance → Modelが21.6%減、Result → Solutionが23.1%減でした。
- v3 OneHotは同じv3 regular比で、Instance → Model時間の中央値が18.8%増、Result → Solution時間の中央値が1.5%増でした。ピークメモリ中央値はそれぞれ9.3%増、7.0%増でした。
- Preparation専用workloadのv3 directはv2比で、Instance → Model時間の中央値が38.1%増、Result → Solution時間の中央値が12.7%増でした。これはPreparation履歴ではなく、v2の通常制約＋hintとv3のnative OneHot変換経路を含む差です。
- Preparation履歴によるInstance → Model差は、時間中央値が0.1%減、メモリは全9ケースで0.0%でした。
- Preparation履歴によりResult → Solutionは、時間中央値が12.0%増、メモリ中央値が19.0%増でした。decodeではremoved制約の評価コストを含みます。
- prepare単体は0.088〜0.961 ms、13.859〜109.289 KiBでした。prepare・変換・decodeの中央値を合算すると、preparedはdirect比で中央値19.6%増でした。

## 測定条件

- 時間：ms。ウォームアップ3回後、20回の中央値
- メモリ：KiB。memrayによる2回目のピーク
- メモリはallocator境界の影響で個別ケースの振れが大きいため、全体傾向はケースごとの比率の中央値で判断
- 初回時間・初回メモリはraw CSVへ保存
- 比較率：`(比較対象 - baseline) / baseline`
- seed：0
- solver：未使用。決定的な実行可能解からdimod SampleSetをローカル生成
- SampleSet：各ケース1サンプル
- v2：OMMX 2.6.1 / dimod 0.12.20 / D-Wave System 1.29.1 / Adapter 0.1.2.dev9+g9f596cb86
- v3：OMMX 3.0.0b4 / dimod 0.12.20 / D-Wave System 1.29.1 / Adapter 0.1.2.dev38+g064425598
- 全414測定が成功（v2: 168、v3: 246）
- raw CSV：各branchの `benchmark_results/20260831-beta4/`（git管理外）
